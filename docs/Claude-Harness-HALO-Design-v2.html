2. The prefix-cache advantage — scoped

Every request the harness sends is a byte-exact extension of the previous one. Append-only log; compaction, pruning, and plan-mode are cache-safe surface replacements; the tool catalog never changes between modes; their CI fails if cache-read tokens hit zero.

Paired with your contextCheckpoints: 32 load config, LM Studio almost never re-processes the prompt. Scoped correctly: prefix reuse eliminates repeated prefill (time-to-first-token on long sessions) and nothing else — decode stays bandwidth-bound, compaction still costs one planned re-prefill, a changed prefix still invalidates. On HALO (~256 GB/s vs a 5090's ~1,792 GB/s) repeated prefill is the most punishing cost, so removing it matters more here than on fast hardware. A real fit, not magic. Phase 2 measures prefill speed and cache hits separately from decode — the argument lives or dies on those numbers.

TTL

Worker loads on demand, unloads idle — bench decides residency

Concurrency reality: two loaded models are two software queues on one iGPU sharing one memory bus. Concurrent decoding contends. Co-residency buys swap-free worker turns and overlap while the brain waits — nothing more until measured. True second-model footprint: weights + second KV cache + compute buffers + vision projector + MTP state, and the machine must stay usable for Codex, Claude, browsers, and tests. Hence bench-gated residency.

Truth-source rule: what is loaded is decided by lms ps --json — never the REST catalog, never labels. MTP accept rates are content-dependent (high on code, lower on prose), so the bench reports per task type. Q4_K_M stays installed as rollback; OpenCode needs zero changes.

Queue policy (resource management): interactive turns outrank background local inference · fixed-time background jobs use cloud/free routes · local background only in idle windows · small aux tasks to cheaper routes · every scheduled run logs provider, model, times, outcome · never two simultaneous turns at one model identity when latency matters · never rename the lmstudio id or model identifiers.

8. Implementation phases

Install and wire (one sitting). Node 22+ → confirm npx @deepseek-ai/dsh@0.1.0-rc.7 still resolves; record resolved version + tarball hash beside the config dump (RC tags can move — the hash is the real pin) → pinned install → .env → settings.yaml provider → launcher → dsh web --dump-config verification → smoke test: fresh session at C:\ discovers a repo, reads, edits, runs tests, prepares (doesn't push) a commit, and reads + edits a scratch file outside that repo — proof the full-drive boundary matches the config. Community dsh-plugin packages are third-party code: read before installing any.
Baseline and bench. Single-Q5 Standard baseline first. Validate real prefix-cache behavior: prefill tok/s and cache hits measured separately from decode. Then five load configs: Q5 alone · Coder alone · both idle · both generating · a full task on each; plus Standard vs Code mode on the winner. Judge on correctness, wall-clock, failed tool calls, recovery, contention, and memory left for the rest of the machine. Worker stays only if complete-task wall-clock justifies its footprint.
Reach. BrowserMCP + extension → navigation, extraction, screenshot, one reversible signed-in action. Memory MCP → store, recall from a fresh session. halo-standard preset with Codex/Claude rows → one task each on existing auth. Ten-minute OpenCode ACP probe — wire only if OpenCode speaks ACP server-side, no custom bridge.
Harden. Restart + reboot persistence · resume across a forced compaction · job start/kill · both models unload, memory returns · back up .dsh to ConfigBackups · launcher polish · autostart only after all pass.
Hermes ops plane (bounded, optional). Owns only what needs no open Harness session: durable cron, messaging delivery, monitoring, skill capture, operational memory. Separate pinned install and home, same LM Studio identity, queue policy enforced, skills proven in a disposable profile first, no autostart until cron persistence survives restart. Gate: existing scheduled Claude agents already cover part of this lane — install only if the delta (messaging, skill learning) is worth a second gateway.
Mission Control (thin, last). One read-only page over native state: health of dsh/Hermes/OpenCode/LM Studio, loaded model + quant + context + queue, sessions, schedules, jobs, launch links, explicit Load Q5 / Load Worker / Unload controls. Duplicates nothing; deletable without impact.

9. Acceptance criteria

  • Launcher opens the Web UI with no terminal steps.
  • Fresh session starts at C:\ in danger-full-access / never.
  • Brain reports 65,536 context via the stable id; vision + tool calls pass end-to-end.
  • Standard completes the bench task; Code mode becomes default only if it wins.
  • Prefill speed and cache-hit rate measured and recorded; cache reads non-zero in steady state.
  • A session crosses an automatic compaction and continues correctly.
  • Five-config concurrency bench recorded; worker residency decision cites its numbers.
  • BrowserMCP drives the signed-in Chrome profile.
  • Memory recalls a stored fact in a brand-new session.
  • Codex and Claude Code subagent tasks succeed on existing auth.
  • OpenCode still works, unchanged, against the same Q5 identity.
  • Everything survives restart and reboot; models unload cleanly, memory returns.
  • If Hermes installed: jobs run with Harness closed, log auditable outcomes, survive restart without duplication, never preempt interactive turns.
  • Mission Control observes and launches without becoming a required dependency.

Rollback

  • Q4_K_M untouched; verified Q5 backup retained; harness pinned with its config dump saved.
  • All local behavior in settings.yaml + home patch + user preset; stock install never modified.
  • Deleting C:\Users\scott\.dsh removes the harness completely; OpenCode unaffected throughout.
  • Hermes in its own profile/home, independently backed up, disablable without touching Harness.
  • Mission Control holds no irreplaceable state.

Telemetry audit — 17 Aug 2026

All 199 installed DeepSeek packages swept (code and config files), telemetry subsystem read at source, live process sockets inspected. Clean. Qwen GGUFs are inert weights — no Qwen code executes (LM Studio is the runtime). The harness ships one telemetry exporter (default target harness-telemetry.deepseeksvc.com), default DISABLED; the disabled path constructs no SDK whatsoever, both enable env vars are unset, and no third-party analytics exist anywhere in the install. Live harness processes hold exactly one connection: localhost LM Studio. The /delta-scan-halo skill re-checks telemetry defaults on every upstream release before any re-pin. Full evidence: halo-stack/docs/AUDIT-telemetry-2026-08-17.md.

Locked defaults: Q5 + Standard stays the cockpit (prefill pain neutralized by the cache: 108.6 s → 13.4 s TTFT). The Coder MoE wins fan-out at 4.3× wall-clock, running on demand with a 2 h TTL (~16 GB returns on idle). Code mode lost 65 vs 41 s — not default. The prefix-cache architecture is validated with hard numbers; pre-bench "≈ parity" decode estimates did not survive measurement.
