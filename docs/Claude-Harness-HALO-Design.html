1. Executive decision

Install DeepSeek Harness (dsh) pinned at 0.1.0-rc.7 as the cockpit. Keep OpenCode untouched. Run two local models on the one LM Studio server: the dense Q5 27B as the brain, the MoE coder as the fast worker for fan-out.

Verified now (via lms ps --json): Qwen3.8-27B UD-Q5_K_XL loaded under stable identity qwen/qwen3.8-27b, context 65,536, vision on, tool-trained, pinned by Load-OpenCode-Qwen.mjs. Q4_K_M retained as rollback.

Permissions are set by environment variable, not config patches: DSH_PERMISSION_MODE=danger-full-access flips the sandbox to full access and approval to never in one move (source-verified). The launcher starts from C:\, so the workspace root is the whole drive.

Nothing custom gets built until a shipped extension point fails. 400+ community plugins already exist under the dsh-plugin GitHub topic — search there first, always.

2. Why this harness fits HALO — the prefix-cache insight

The load-bearing finding of the source dive: every request the harness sends is a byte-exact extension of the previous one.

The session log is append-only. Compaction, tool-result pruning, and plan-mode are all engineered as cache-safe surface replacements; the tool catalog never changes between modes (their own source comments say: for request-cache stability). Their CI fails if cache-read tokens drop to zero. Even the compaction summarizer is shaped as a prefix-extension of the already-warm request.

Your LM Studio config already runs contextCheckpoints: 32 on a single slot. Stable prefixes + checkpoints = LM Studio almost never re-processes the prompt. Scoped correctly: prefix reuse eliminates repeated prefill (time-to-first-token on long sessions) and nothing else — decode stays bandwidth-bound, compaction still costs one planned re-prefill, and a changed prefix still invalidates the cache. On HALO (~256 GB/s vs a 5090's ~1,792 GB/s) repeated prefill is the most punishing cost, so removing it matters more here than on fast hardware. A real fit, not magic.

4. What the source dive established

Three parallel subagent sweeps over the reviewed clone at tag dsh-v0.1.0-rc.7: kernel/config, agent runtime, integrations. Facts below are from source, with file-level citations held in the session record.

Install & home

npx @deepseek-ai/dsh@0.1.0-rc.7 web → UI at 127.0.0.1:3080. Node ≥22.19. Home: C:\Users\scott\.dsh holds profiles, sessions, skills, presets, credentials, home patch. --host 0.0.0.0 is rejected — local only.

Config layering

bundles → profile patch → home cordis.patch.yml → --patch overlays. A patch replaces the row's whole config — no merge. Verify every change with dsh web --dump-config.

Permissions

DSH_PERMISSION_MODE=danger-full-access sets sandbox and flips approval to never. Workspace root = launch dir. No rows patched. Runtime switch: /permission.

Presets

standard (default, full tools) · code (same registry + run_code) · minimal · cordis (Creator — agent edits compositions). User presets: .dsh\.agent-presets\.

Compaction

Trigger 80% → 52,428 tokens at 65,536 ctx. Retain 16% → 10,485. Summary cap 8,192. Tool results >8,192 chars pruned first (head 4,096 / tail 1,024). Overflow auto-recovers. Ship defaults.

Qwen dialect

The generic provider has compat.thinkingFormat: qwen — a dedicated Qwen reasoning parser. Set it on the LM Studio route. Context budget for compaction comes from the declared contextWindow.

Subagents

Ship: in-process spawn/fork (model overridable), codex, claude-code (official SDK, native auth), generic ACP client, child-dsh. Plus workflows and the Ralph loop (explicit ask only).

MCP & browser

One plugin row per MCP server (stdio/http), tools as mcp__server__tool. No browser control ships at all — BrowserMCP against signed-in Chrome is the right first add.

Windows native

pwsh -NoLogo -NoProfile -NonInteractive, UTF-8 forced, PS7 first, taskkill /T /F tree kill, 64 MiB output spill. Native Win32 paths. No WSL anywhere.

5. Model layer — two models, not one

Q5_K_XL

Brain — verified loaded, stable id qwen/qwen3.8-27b

MoE A3B

Worker — on-demand; measured decode ≈ parity with Q5+MTP; swap-free fan-out

2 queues

Fan-out no longer waits behind the main turn

TTL

Worker loads on demand, unloads idle — bench decides residency

Main break from the Codex paper: it shared one loaded model, so every subagent queued behind the cockpit. HALO's unified memory can hold a second model, so worker turns run swap-free — but both share one iGPU's bandwidth, so concurrency is contention, not a free second engine. Measured decode is near parity (Q5+MTP ≈ 28.3 tok/s vs A3B MoE ≈ 30–37 tok/s). The Phase 2 bench — Q5 alone · Coder alone · both idle · both generating · a full task on each — proves or kills this with data.

Truth-source rule: what is loaded is decided by lms ps --json — never the REST catalog, never labels. The Q5 loader script stays authoritative; a second pinned loader (Load-Worker-Coder.mjs, TTL-based, unloads when idle) makes the worker deterministic.

8. Implementation phases

Install and wire (one sitting). Node 22+ check → pinned install → .env credential → home patch → launcher → verify with dsh web --dump-config → smoke test: fresh session at C:\ discovers a repo, reads, edits, runs tests, prepares (doesn't push) a commit.
Bench day. First a single-Q5 Standard baseline + real prefix-cache validation (prefill tok/s and cache hits measured separately from decode). Then five load configs: Q5 alone · Coder alone · both idle · both generating · a full task on each; plus Standard vs Code mode on the winner. Judge on correctness, wall-clock, failed tool calls, recovery, contention, and memory left for the rest of the machine. The worker stays loaded only if complete-task wall-clock justifies its footprint.
Reach. BrowserMCP + extension → navigation, extraction, screenshot, one reversible signed-in action. Memory MCP → store, then recall from a completely fresh session. Enable halo-standard with Codex/Claude rows → one task each. Ten-minute OpenCode ACP probe; wire it only if OpenCode speaks ACP server-side — no custom bridge.
Harden. Restart + reboot persistence · resume across a forced compaction boundary · background job start/kill · both models unload and memory returns · back up .dsh to the ConfigBackups dir · then desktop launcher polish, autostart, and a creator-mode mission-control panel as the first Creator experiment.

9. Acceptance criteria

  • Launcher opens the Web UI with no terminal steps.
  • Fresh session starts at C:\ in danger-full-access / never.
  • Brain reports 65,536 context via the stable id; vision and tool calls pass end-to-end.
  • Standard mode completes the bench task; Code mode becomes default only if it wins.
  • A session crosses an automatic compaction and continues correctly.
  • Cache-hit rate is visibly non-zero after the first turns.
  • Worker serves a subagent turn while the brain is mid-turn (two-queue proof).
  • BrowserMCP drives the signed-in Chrome profile.
  • Memory recalls a stored fact in a brand-new session.
  • Codex and Claude Code subagent tasks succeed on existing auth.
  • OpenCode still works, unchanged, against the same Q5 identity.
  • Everything survives app restart and a Windows reboot; models unload cleanly.

Rollback

  • Q4_K_M untouched; verified Q5 config backup retained.
  • Harness pinned at 0.1.0-rc.7; effective config dump saved beside the backup.
  • All local behavior in home patch + user preset — stock install never modified.
  • Deleting C:\Users\scott\.dsh removes the harness footprint completely; OpenCode unaffected throughout.
Bottom line: pinned harness cockpit · env-var full access · brain/worker two-model split · ship-default compaction riding a prefix-cache-stable request shape · BrowserMCP + memory MCP · Codex/Claude escalation · OpenCode untouched · nothing custom until something shipped fails.
