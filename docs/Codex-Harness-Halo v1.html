1. Executive decision

Use DeepSeek Harness Web UI as the prospective primary interactive coding cockpit, preserve OpenCode Desktop as an independent coding and cloud-model interface, and add Hermes Agent later as a separate operations plane for cold-session schedules, messaging, memory and learned skills.

Model status: Unsloth Qwen3.8-27B UD-Q5_K_XL is installed, verified and now the OpenCode daily default. Q4_K_M remains installed as the fast rollback profile.

Do not build a replacement harness. DeepSeek Harness already supplies native Windows shell and filesystem tools, managed jobs, subagents, workflows, automatic compaction, session replay, skills and MCP integration. Add browser control and cross-session memory through existing MCP servers before writing custom plugins.

Start Qwen in Harness Standard mode. A/B-test Code mode later. Add Hermes only after this baseline is stable, and expose both through a thin mission-control page rather than creating another orchestration framework.

2. Interactive coding plane

This is the foundation built first. The later Hermes operations plane shares its model and capabilities through an explicit queue policy; it does not replace this coding plane.

3. What the source-level DeepSeek review established

Composition

Profiles are ordered bundles plus profile, home and optional overlay patches. Local behavior can remain an overlay instead of a source fork.

A targeted row's config is replaced rather than recursively merged, so the effective configuration must be dumped and validated after edits.

Standard agent

Already includes PowerShell, filesystem tools, search, jobs, skills, planning, compaction, subagents, workflows, Ralph, questions and task tracking.

Code mode

Lets Qwen batch tool operations through generated TypeScript. Potentially faster, but dependent on reliable code generation and process cleanup.

Windows native

Uses PowerShell and native Win32 paths. No Linux workspace or WSL translation is required.

Full Windows-user capability

Persistent target: workspace C:\, permission mode danger-full-access, approval policy never, native PowerShell, network and process execution enabled.

Harness then imposes no workspace-only filesystem or shell confinement. Effective capability matches the signed-in Windows account across the drive. Remaining limits are Windows ACLs, UAC/elevation, file locks and provider limits. Fresh sessions are required after changing the persistent permission default because sessions pin their permission state when created.

5. Browser-controlling agent

DeepSeek Harness does not ship a production interactive browser controller. Its repository's Playwright usage tests the Harness UI; the Web UI does not automatically provide the agent with a page DOM or screenshot. The transcript's Augmentor-style browser worker was an added component.

1 · BrowserMCP

Recommended first. Controls the existing Chrome profile locally and keeps signed-in sessions. Best match for YouTube, authenticated dashboards, comments, admin pages and real browser state.

2 · Browser Use

Evaluate for longer self-healing tasks, isolated browser instances and repeatable automation when BrowserMCP proves insufficient.

3 · Custom plugin

Build only after an existing MCP path demonstrates a concrete limitation. Do not create a second browser framework preemptively.

6. Subagents and model routing

Harness supports in-process subagents, optional Codex and Claude Code providers, generic ACP agents, and complete child Harness processes. The source has no ready-made OpenCode subagent adapter; ACP compatibility must be verified before considering a custom bridge.

Concurrency reality: LM Studio has one inference slot. Multiple local Qwen agents queue rather than run in parallel. Keep local work sequential; use cloud workers for true concurrent fan-out.

7. Memory, research and resource policy

Memory

Harness's append-only session log already provides resume, fork, replay and session search. Add one existing MCP memory server for cross-session recall: start with MCP Reference Memory, evaluate Memorix if richer retrieval is needed, and keep substantive research as visible Markdown or JSONL files.

Resource rules

  • Retain the 64 GB system / 64 GB VGM split.
  • Share one loaded Qwen model between Harness, OpenCode and any later Hermes profile.
  • Avoid simultaneous Qwen turns from multiple applications when latency matters.
  • Keep parallel: 1.
  • Keep the model unloadable so other Windows and AI workloads can reclaim memory.
  • Do not autostart Harness or Hermes until their restart and endurance tests pass.
  • Avoid unnecessary parallel browser instances because Chrome can consume substantial RAM.

Bounded responsibilities

Interactive plane

DeepSeek Harness: repository coding, full-drive shell/filesystem work, tests, Git, visible plans, traces, compaction, session forks and active-task subagents.

OpenCode: independent coding UI and cloud-model catalog.

Operations plane

Hermes: durable cron, messaging delivery, background research/monitoring, cross-session operational memory and controlled procedural skill improvement.

Control plane

Mission Control: service health, queues, schedules, logs, loaded model, memory pressure and links to native interfaces. It owns no irreplaceable state.

Shared-model queue policy

  1. Interactive Harness/OpenCode work has priority over background local inference.
  2. Hermes jobs that must run at a fixed time use a cloud/free route when local coding may be active.
  3. Local Hermes jobs run in configured idle windows or after an explicit queue check.
  4. Auxiliary compression, title or extraction tasks use smaller/cheaper routes where practical.
  5. Every scheduled run records provider, model, timing, outcome and error state.

Mission Control scope

Build it last as a thin web page showing Harness, Hermes, OpenCode and LM Studio health; loaded quant/context and memory; active sessions; schedules and next run; jobs/subagents; BrowserMCP connection; recent failures; and explicit Q5/Q4 load and unload controls. It must not duplicate chat databases, schedulers, permissions or model-routing state.

Benchmark Standard versus Code mode. Use identical representative repository work and select by correctness, task time, recovery and cleanup.

Add persistent memory. Test a stored decision and its recall from a completely fresh session.
Enable external agents. Configure official Codex and Claude providers; test OpenCode ACP before any custom bridge.
Add Hermes operations profile. Pin the native Windows release; validate LM Studio routing, procedural skills, memory, cron persistence and one delivery channel.
Run the production audit. Exercise compaction, resume, forks, cron, background jobs, queue contention, process cleanup, model unloading, restart and reboot persistence.
Add Mission Control and launchers. Build the thin status/launch page only after every underlying service passes independently.

10. Acceptance criteria

  • Harness opens from a desktop launcher without a CLI workflow.
  • A fresh session starts at C:\ with persistent Windows-user capability.
  • Qwen Q5 is selected through the stable ID and reports 65,536 context.
  • The agent discovers repositories anywhere on C:\ without Scott locating them.
  • It edits, installs dependencies, runs tests, executes Git and uses the network.
  • Standard mode completes representative coding reliably.
  • Code mode becomes default only if its benchmark wins.
  • Compaction preserves state through a long task.
  • BrowserMCP operates the intended signed-in Chrome session.
  • Persistent memory recalls information in a new session.
  • Codex and Claude tasks succeed using existing authentication.
  • OpenCode remains independently functional.
  • Closing/unloading returns memory to other Windows applications.
  • Configuration survives application restart and Windows reboot.
  • Hermes jobs, when enabled, run while Harness is closed and leave an auditable result.
  • Hermes memory and learned skills are inspectable, isolated and reversible.
  • A scheduled Hermes job cannot silently contend with active interactive Qwen work.
  • Mission Control can close or fail without stopping any underlying service.

Rollback and recoverability

  • Keep Q4 installed and untouched.
  • Retain the verified Q5 backup.
  • Pin the Harness version and store its effective config dump.
  • Use overlays instead of modifying official source.
  • Keep OpenCode working throughout deployment.
  • Back up Harness home before structural changes.
  • Keep Hermes in a separate profile/home with independent memory and skill backups.
  • Mission Control stores no irreplaceable state.
  • Record exact MCP/plugin versions and configurations.
Final recommendation: Harness Standard as the initial interactive coding cockpit; OpenCode retained independently; LM Studio serving verified Q5 and retained Q4; full C:\ Windows-user capability; BrowserMCP for signed-in Chrome; official Codex/Claude providers; then Hermes as a bounded operations plane for cold-session cron, messaging, memory and learned skills. Add Mission Control last as an observability/launch surface, never as another stateful agent framework.
